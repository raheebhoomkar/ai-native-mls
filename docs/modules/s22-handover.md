## Design (decided in chunk 1, recorded in ADR 0007)

- **One Vercel project, two services** (`vercel.json`): `web` (the Vite build, static, with an SPA fallback) and `api` (a container built from `services/api/Dockerfile`, so Python 3.15 and OpenCV work without depending on Vercel's Python runtime). Public routes: `/api/*` to `api`, everything else to `web`. Same origin, so the session cookie works unchanged.
- **Background jobs without an always-on worker.** `GET /api/v1/ops/run-jobs` runs due jobs for up to 50 seconds and queues the daily cleanup. It needs `Authorization: Bearer <CRON_SECRET>`; without `CRON_SECRET` it answers 404. Vercel Cron calls it with that header. Hobby plans allow one cron run a day, so the guide says how to call it every minute from a free external scheduler, or how to run `python -m app.worker` as a Vercel daemon.
- **Start-up.** The container runs `start.sh`: migrations and the optional demo seed, under one Postgres advisory lock so cold starts at the same moment do not race; `RUN_WORKER=false` keeps the in-container worker off on Vercel.
- **Media** must be an S3-compatible bucket (`MEDIA_STORAGE=s3`, for example Cloudflare R2): a container's disk is not shared or kept.
- **Database:** any Postgres URL (Neon from the Vercel Marketplace works); `postgres://` URLs are already accepted.
